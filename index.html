Inside an AMD EPYC processor

An EPYC processor isn’t one giant chip. It’s a set of small compute chiplets (AMD calls them CCDs, each holding 8 Zen cores) arranged around a central I/O die that connects them to memory.

Each layer of that design sets a different speed limit. Read the diagram below top-down for prefill and bottom-up for decode:

A practical tip: when you slice a socket into small virtual machines, you lose memory bandwidth along with cores, because each CCD brings its own links to memory. Give inference workloads whole CCDs where you can.

What we measured on EPYC

More users, more throughput, longer waits

Running requests side by side multiplies what the same cores deliver. The trade-off is waiting: as requests queue for prefill, the first token takes longer.

Long prompts are the real bottleneck

Our slice reads prompts at about 850 tokens per second, so the wait for the first token grows in a straight line with prompt length:

A 4,096-token prompt (roughly 3,000 words) takes 5 seconds to read before the answer starts, and nearly 20 seconds when eight requests queue up. This is the compute-bound phase at work, and exactly what Turin’s native 512-bit math targets.

How we compare with AMD’s tuned reference

AMD published results for Llama 3.1 8B on a 64-core EPYC 9555 (Turin, Zen 5) running its optimized AIM stack. We ran the same workload shapes and concurrency on our 24-core Genoa slice:

On raw totals we trail. But we also used 37.5% as many cores, an older generation and an untuned stack. Divide by cores and a clearer picture appears:

Per core, we already match AMD on prompt-heavy Translation and trail most on decode-heavy Chatbot. That points at memory bandwidth and the serving stack, not core count, as the first things to fix.

Keeping it honest: AMD reports a first token in 0.23 to 0.34 seconds and about 8 to 9 tokens per second per user. At the same high concurrency our medians were far slower: 14 to 49 seconds to the first token and 268 to 311 ms per token, although all 76 chatbot requests completed. Model precision, quantization and engine settings were not matched, so treat the comparison as directional.
